# 色彩阶梯 · R2 / R3 深度规格

> 什么时候读这份：Phase 2.5 配色面板调参、`check-tokens.mjs` 报 `R2` / `R3` / `A11Y` / `T2`、写 `contract.md` 第 3 段、导演层已经给了色板需要补齐阶梯。

本文覆盖：**ΔL 的锁死定义**、color policy、层阶生成公式、色相漂移、描边阶梯、WCAG 阈值、sRGB 色域映射。R2 / R3 的一行版在 [`00-non-negotiable.md`](00-non-negotiable.md)。

## 1. ΔL：唯一允许的定义

```
ΔL = |L₁ − L₂|
```

- `L` 是 **OKLCH 的 L 通道**，取值 `0–1`（不是百分比字符串，不是 WCAG 相对亮度）
- 结果是一个**绝对差值**，落在 `[0.010, 0.030]`
- 低于 0.010：低质量屏幕、低亮度、强环境光下不可见，层级等于没有
- 高于 0.030：层级"浮起来"，看起来是卡片叠在卡片上，而不是同页面的两个层级

**三种常见写错，全部判违规：**

| 写法 | 实际含义 | 判定 |
|---|---|---|
| `ΔL ∈ [1%, 3%]` | 相对百分比 `\|L₁−L₂\|/L₁` | ✗ 不是本规则 |
| `相对亮度差 1%–3%` | WCAG 相对亮度 | ✗ 不是本规则 |
| `L 值相差 1–3`（0–100 刻度） | 换算后是 `0.01–0.03`，数值对但刻度没写清 | ⚠ 必须写明是 0–1 刻度 |

**容器 `L` 的刻度是 0–1。** `oklch(98.5% 0.002 85)` 与 `oklch(0.985 0.002 85)` 等价，但 token 表里**一律写小数**，方便直接相减。

### 1.1 代码里的唯一定义

`scripts/lib/oklch.mjs` 导出：

```js
/** ΔL — the ONLY definition used across this skill: absolute difference of OKLCH L. */
export const deltaL = (a, b) => Math.abs(a.L - b.L);
```

`check-tokens.mjs` 的判定带 `1e-9` 容差，**0.010 与 0.030 本身是合法的**：

```js
if (d < 0.010 - 1e-9 || d > 0.030 + 1e-9) { /* R2 error */ }
```

不要为了"保险"把 step 调到 0.011 或 0.029——边界值不用白不用，而且它通常正是别处视觉校验过的那一档。

## 2. color policy

L1 的判定依据。写进 `tokens.css` 之外的任何颜色都要过这几条。

| 项 | 规则 | 违规 id |
|---|---|---|
| **允许的色值格式** | `oklch()`、`#hex`、`rgb()`。写进 token 表之外的一律违规 | `T2` |
| **hex 位宽** | `#rrggbb`（6 位）或 `#rgb`（3 位）。4 位 / 8 位带 alpha 的 hex 不被 `decisions.schema.json` 接受 | `E002` |
| **允许的 alpha** | 阴影、玻璃边缘、叠加遮罩可以用 alpha；**正文色 alpha 不得低于 0.9** | `T2` / 人工 |
| **纯黑** | 不透明 `#000` / `rgb(0 0 0)` / `oklch(0 0 0)` 不得用于文字、背景、边框、图标；带 alpha 的黑只用于阴影与暗线 | `R3` |
| **对比度** | WCAG 2.2 AA：正文 4.5:1，大字 3:1，非文本与焦点 3:1 | `A11Y` |
| **色域** | `oklch()` 超出 sRGB 时按 CSS Color 4 做 gamut mapping，并记 `gamutClipped` | 人工 / `tokens.json` |

### 2.1 alpha 规则的细节

正文色下限 0.9 不是随手定的：`--fg` 在 `#FBFAF9` 上 alpha 0.9 之后对比度约 13.4:1，仍远超 4.5；降到 0.6 就只剩 5.2:1 左右，遇到次要表面直接擦线。**需要"变淡"的文字请用 `--fg-muted` 这个 token，不要给 `--fg` 加 alpha。**

```css
/* ✗ 错：正文用 alpha 做次要感 */
.helper { color: color-mix(in oklab, var(--fg) 55%, transparent); }

/* ✓ 对：次要文本有自己的 token */
.helper { color: var(--fg-muted); }
```

阴影与玻璃边缘不受这条约束——它们是**混合工具**，本来就该带 alpha。

### 2.2 纯黑的豁免范围（R3 的核心）

| 场景 | 允许 `<alpha>` 黑 | 允许不透明黑 | 依据 |
|---|---|---|---|
| 投影 `box-shadow` / `text-shadow` | ✓ `rgb(0 0 0 / .18)` | ✗ | 混合工具 |
| 玻璃边缘暗线 `inset 0 -1px 0 rgb(0 0 0 / .08)` | ✓ | ✗ | 混合工具 |
| 叠加遮罩 `background: rgb(0 0 0 / .5)` | ✓ | ✗ | 混合工具 |
| 正文 `color` | ✗ | ✗ 用 `#1A1A19` | R3 |
| 页面背景 `background` | ✗ | ✗ 用 `--bg` | R3 |
| 普通边框 `border` | ✗ | ✗ 用 `--line-*` | R3 |
| 图标填充 `fill` / `stroke` | ✗ | ✗ 用 `currentColor` | R3 |
| 打印样式 | — | ✓ | 打印不需要色温 |
| 风格卡声明的硬描边 | — | ✓ 需 override | 新粗野主义 / 像素风 |

**L1 按使用场景判定，不按字面扫 `000`。** `check-tokens.mjs` 的做法是看该行是否含 `shadow` / `inset` / `color-mix` / `rgba(` / `transparent`，含则放行；同时单独匹配 `rgba(0, 0, 0, .N)` 这种 alpha 形式。

```css
/* ✓ 通过：行内有 shadow，且是 alpha 形式 */
box-shadow: 0 1px 2px -1px rgb(0 0 0 / .18);

/* ✗ 报 R3：不透明黑，且不在阴影上下文 */
border: 1px solid #000;

/* ✗ 报 R3：oklch 的纯黑，L 与 C 都是 0 */
background: oklch(0 0 0);
```

### 2.3 `#1A1A19` 的精确值

```
#1A1A19  =  oklch(0.2174 0.0019 106.6)
```

- **四位小数，不许手写近似值**。写成 `oklch(0.217 0.002 104)` 会让 `check-consistency` 的 hex/oklch 对照失败，也会让 `--fg` 在十六进制反查时对不上。
- 这是一个**暖调深灰**（H 106.6 略偏黄绿，C 0.0019 几乎中性），不是"带一点点蓝的黑"。写错色相会让整页色温和 `--bg` 的 H 85 打架。
- 它是浅色主题的唯一正文色。不要为它再做一个 `--fg-strong` 去压到更黑——需要更强可以用字号或字重，不是用更黑的颜色。

## 3. 层阶生成公式

表面阶梯**只动 L，锁死 C 与 H**。这是"层级不脏"的唯一保证。

```js
// scripts/lib/oklch.mjs
export function surfaceLadder(base, count = 3, step = 0.015) {
  const s = Math.min(0.030, Math.max(0.010, step));   // 硬夹在 [0.010, 0.030]
  const out = [{ ...base, level: 0, deltaFromPrev: null }];
  for (let i = 1; i <= count; i++) {
    out.push({ L: base.L - i * s, C: base.C, H: base.H, level: i, deltaFromPrev: s });
  }
  return out;
}
```

### 3.1 浅色阶梯（参考实现）

| Token | oklch | hex | L | 相对上一层 ΔL | 用途 |
|---|---|---|---|---|---|
| `--bg` | `oklch(0.985 0.002 85)` | `#FBFAF9` | 0.985 | — | 页面底 |
| `--surface-1` | `oklch(0.975 0.002 85)` | `#F7F7F5` | 0.975 | 0.010 | 卡片 |
| `--surface-2` | `oklch(0.960 0.002 85)` | `#F2F2F0` | 0.960 | 0.015 | 浮层 |
| `--surface-3` | `oklch(0.943 0.002 85)` | `#EDECEB` | 0.943 | 0.017 | 弹窗 |
| `--surface-sunken` | `oklch(0.968 0.002 85)` | `#F5F4F3` | 0.968 | — | 输入框底（R4） |

**阶梯不是等距的，这是有意的。** 0.010 / 0.015 / 0.017 是"越往上越容易分辨"的递进：最上面那层通常最容易被忽略，所以给它最大的差。等距 0.015 × 3 会让第一层几乎看不见。

`--surface-sunken` **不参与阶梯排序**——它是"凹陷"方向，与表面阶梯不是同一条链，`check-tokens` 的阶梯重算只取 `^surface-?\d+$`。

### 3.2 暗色阶梯

暗色**独立生成，不反转浅色**。反转会让高光消失、把阴影语义弄反。

| Token | oklch | hex | L | 相对上一层 ΔL |
|---|---|---|---|---|
| `--bg` | `oklch(0.180 0.002 85)` | `#121111` | 0.180 | — |
| `--surface-1` | `oklch(0.202 0.002 85)` | `#171615` | 0.202 | 0.022 |
| `--surface-2` | `oklch(0.226 0.002 85)` | `#1C1C1B` | 0.226 | 0.024 |
| `--surface-3` | `oklch(0.252 0.002 85)` | `#222221` | 0.252 | 0.026 |

暗色阶梯往上走是**变亮**，不是变暗。L 递增，ΔL 仍然取绝对值，所以公式不变。

**暗色的 step 通常比浅色大**（0.022–0.026 vs 0.010–0.017）。原因：暗底上小面积的低对比区域更难分辨，同样的 ΔL 在暗色下主观对比更弱。上限仍是 0.030。

### 3.3 生成顺序

```
1. 定 --bg 与 --fg  →  先把正文对比度打到 ≥ 4.5:1（通常远高于此）
2. 定 --surface-1/2/3 的 step 序列，每步夹进 [0.010, 0.030]
3. 用 oklchToHex 落出 hex，写进 tokens.css 的注释
4. 生成暗色（独立一轮，从 --bg 的暗色值起算）
5. 检查 gamutClipped，超界的降 C
6. 重算每级对比度，跑 A11Y
```

Studio 配色面板按这个顺序开放旋钮：先调 `--bg` 的 L / H，再调 step，再调 accent。**不允许先调 accent 再反推背景**——那会把对比度当结果而不是约束。

## 4. 色相漂移 ≤ 2°

同一色阶内相邻两级的 OKLCH **H 差值绝对值必须 ≤ 2°**，**C 必须完全一致**。

```
✓  oklch(0.975 0.002 85)  →  oklch(0.960 0.002 85)     ΔH = 0
✓  oklch(0.975 0.002 85)  →  oklch(0.960 0.002 87)     ΔH = 2     （边界，合法）
✗  oklch(0.975 0.002 85)  →  oklch(0.960 0.004 92)     ΔH = 7, ΔC = 0.002
```

**为什么允许 2° 而不是 0：** 手工调色时为了让某一层"稍暖一点"会微调 H；2° 在肉眼上不可辨，但足以在低质量屏上避免色带。超过 2° 就进入"两个不同颜色"的范畴，不是同一阶梯了。

**C 必须严格相等。** 一旦 C 变了，表面就会在暗色模式下"跑色"——暗色会放大彩度差，浅色下看不出的 0.002 在暗色下会变成明显的冷暖跳变。

## 5. 描边阶梯独立

描边**不参与表面层级**，也不用 ΔL 校验。它有自己的 `--line-*` 阶梯。

| Token | 浅色值 | 暗色值 | 用途 |
|---|---|---|---|
| `--line-1` | `oklch(0.900 0.002 85)` / `#DEDEDC` | `oklch(0.300 0.002 85)` | 分隔线、卡片边框 |
| `--line-2` | `color-mix(in oklab, var(--fg) 12%, transparent)` | `color-mix(in oklab, var(--fg) 14%, transparent)` | 更强调的结构线 |
| `--line-inset` | `color-mix(in oklab, var(--fg) 8%, transparent)` | `color-mix(in oklab, white 6%, transparent)` | 输入框内环（R4） |
| `--line-hair` | `1px solid var(--line-1)` | 同 | 光学值，1px |

`--line-inset` 在暗色下换正负号（fg → white），这是 R4 的要求：暗底上"变深"不可见。
`--line-hair` 是**光学值 token**，它只承载 1px 这个宽度语义，颜色仍由 `--line-1` 决定。

### 5.1 描边与对比度的一句话

`--line-1` 在浅色上对 `--bg` 的对比度只有约 **1.29:1**。这是**装饰性分隔线**，不受 3:1 约束（WCAG 1.4.11 只约束"识别控件所必需的视觉信息"）。但**控件边界**受约束：

| 用途 | 需要 3:1？ | 该用什么 |
|---|---|---|
| 装饰性分隔线、卡片轮廓 | 否 | `--line-1`（1.29:1） |
| 输入框的可辨识边界 | **是** | `--line-inset` 不够（fg 8% → 约 1.17:1），必须靠 R4 的内外投影，或改用更深的边界 |
| 焦点指示 | **是**（R4 + A11Y） | `--accent` 内环（4.41:1）+ 3px 外环光环 |

**这就是为什么 R4 要三件套。** 想用一条 1px 线同时满足"细"和"3:1"是不可能的——1px 达到 3:1 就已经是 `--fg` 50% 的深灰，视觉上会变成很重的框。

## 6. WCAG 2.2 AA 阈值

| 场景 | 阈值 | 适用范围 | 检查什么 |
|---|---|---|---|
| **正文文本** | 4.5:1 | 字号 < 24px 的常规文字；< 18.66px 的粗体 | `--fg` / `--bg`、`--fg` / `--surface-*` |
| **大字** | 3:1 | ≥ 24px 常规，或 ≥ 18.66px 且 ≥ 700 字重 | 标题、display |
| **非文本** | 3:1 | 控件边界、图标、图表元素、「识别控件所必需」的视觉信息 | 图标、开关轨道、图表线 |
| **焦点指示** | 3:1 | `:focus-visible` 的可见指示，且与相邻颜色（含背景）比 | 焦点环 |
| **次要文本** | 4.5:1 | 不因为"次要"就降阈值 | `--fg-muted` |
| **禁用态** | 豁免 | `disabled` 的元素不受 1.4.3 约束 | 仍建议 ≥ 3:1 以免误读 |

### 6.1 本项目实测矩阵（参考色板）

| 前景 / 背景 | 浅色 | 暗色 | 阈值 | 结果 |
|---|---|---|---|---|
| `--fg` / `--bg` | 16.71:1 | 15.83:1 | 4.5 | ✓ |
| `--fg` / `--surface-3` | 14.76:1 | 13.37:1 | 4.5 | ✓ |
| `--fg-muted` / `--bg` | 5.27:1 | 7.59:1 | 4.5 | ✓ |
| `--fg-muted` / `--surface-3` | 4.65:1 | 6.41:1 | 4.5 | ✓ |
| `--accent` / `--bg` | 4.64:1 | 7.61:1 | 3.0（非文本） | ✓ |
| `--accent` / `--surface-3` | 4.10:1 | — | 3.0（非文本） | ✓ |

`--fg-muted` 在 `--surface-3` 上是 **4.65:1**——只比 4.5 多 0.15。这类"刚过线"的组合必须写进 `contract.md` 的对比度矩阵，因为**任何把 surface-3 再调深一格的操作都会让它跌破**。

### 6.2 表面 ΔL 不能替代可读性检查

这是 R2 里最容易被跳过的一句。

```
✓ 表面 ΔL = 0.017          层级存在
✗ `--fg-muted` 在该层上 4.2:1   可读性不达标
```

两件独立的事：**东西看得见吗（ΔL）** 与 **上面的字读得清吗（对比度）**。ΔL 达标不代表对比度达标，反之亦然。Studio 配色面板并排显示这两个读数，就是为了防止"看着有层级"被误当"能用"。

### 6.3 大字判定

```css
/* WCAG 的大字定义：24px 常规，或 18.66px 且 700 */
.headline { font-size: 24px; font-weight: 600; }      /* 大字 → 3:1 */
.subhead  { font-size: 18px; font-weight: 700; }      /* 大字 → 3:1（≥18.66? 18 不够） */
.body     { font-size: 15px; font-weight: 400; }      /* 正文 → 4.5:1 */
```

**18px 的 700 不是大字**——门槛是 18.66px（14pt）。差 0.66px 就按 4.5:1 测。别赌这一像素，统一按正文测。

## 7. sRGB 色域映射

CSS Color 4 允许 `oklch()` 走出 sRGB。走出之后**不同浏览器会各显神通**（有的截断到最近的色块，有的降饱和度，有的不映射），同一个色值在 Chromium 与 Safari 上会不一样。

**策略：在生成阶段就映射回 sRGB，别交给浏览器。**

```
gamut mapping（CSS Color 4 序列）：
  保持 L 与 H 不动
  二分降低 C，直到进入 sRGB 色域
  结果记录原 C 与实际 C
```

本 skill 的实现（`scripts/lib/oklch.mjs`）：

```js
export function gamutMap({ L, C, H }) {
  const direct = oklchToRgb({ L, C, H });
  if (inGamut(direct)) return { rgb: direct.map(clamp01), clipped: false };

  let lo = 0;
  let hi = C;
  for (let i = 0; i < 24; i++) {          // 24 次二分为精度 ~C/2^24，足够
    const mid = (lo + hi) / 2;
    if (inGamut(oklchToRgb({ L, C: mid, H }))) lo = mid;
    else hi = mid;
  }
  const rgb = oklchToRgb({ L, C: lo, H }).map(clamp01);
  return { rgb, clipped: true, chroma: lo };
}
```

### 7.1 记录要求

超界的色值在 `tokens.json` 里必须记 `gamutClipped: true`，`tokens.css` 里加注释：

```css
--accent: oklch(0.55 0.173 145); /* #008A23 */ /* gamut-mapped */
```

实例子：`oklch(0.55 0.30 145)` 超出 sRGB，映射后 C 从 0.30 降到 **0.173**，落为 `#008A23`。**原值 0.30 与生效值 0.173 都要出现在报告里**——否则用户以为自己的绿是"更饱和的那种绿"。

### 7.2 映射顺序

1. **先生成，后映射**。不要为了避开超界而提前压低所有色值的 C；那会把本来合法的色也一起降饱和。
2. **映射不动 L 与 H**。L 变了会破坏 ΔL 阶梯，H 变了会破坏色相漂移约束。
3. **映射后的色要重跑对比度**。降 C 会轻微改变感知亮度，擦线的组合（如 4.65:1）可能因此跌破。
4. **`--fg` / `--bg` / `--surface-*` 不应出现超界**。中性色 C ≤ 0.012，在 L 0.18–0.99 范围内不可能超界。超界基本只发生在 `--accent` 与大面积彩色底上。

### 7.3 P3 广色域不是目标

`oklch()` 在 P3 屏上能表达更饱和的颜色。本 skill **不利用这一点**：合同里的每个颜色都必须能在 sRGB 上 1:1 渲染，否则"签样"与"实现"会在不同屏幕上分叉。需要广色域的项目必须在 Phase 0 就声明，并把色域写进合同第 9 段。
