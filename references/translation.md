# 转写：把散文变成数字

> 用于 Phase 2。这是 `aesthetic` 的核心动作，也是唯一一个"做错了要到实现阶段才暴露"的环节。

---

## 为什么必须转写

导演层给出的是这些话：

> "工业感、图纸感。像瑞士铁路时刻表那样克制。不要糖水渐变，不要大字报。"
> —— 22 个汉字，零个数字。

如果不转写就直接实现，会出现三个必然问题：

1. **每个人读出的值不同**。本会话的你和下一个会话的 agent，圆角会一个做 0 一个做 8。
2. **无法校验**。`check-tokens.mjs` 只能检查"是否在 token 表内"，而散文不是一个 token 表。
3. **改方向时不知道改哪**。用户说"再冷一点"，你得重新猜一遍全部。

转写把这句话变成七个可以打分的旋钮。**每个旋钮都必须能回答"我从哪句话推出这个值"**——推不出来的写 `null`，说明它是规则默认。

**对用户怎么说**：上面这段不要原样念给用户听。用户听不懂"无法校验""token 表"，只需要一句：「我把你描述的风格翻成七个具体数值，这样开发时不用猜，做完也能一项项核对。」展开来解释时用 `phrasing.md` 的「七维」一行。

---

## 七个维度

| # | 维度 | 影响 token | 取值范围 | 典型误判 |
|---|---|---|---|---|
| 1 | 中性色温度 | `--bg` `--surface-*` `--fg` 的 H 与 C | H ∈ [0, 360]，C ∈ [0, 0.012] | 把"冷"做成纯灰（C=0），丢掉了那点色温 |
| 2 | 彩度上限 | `--accent` 及所有饱和色 | C ∈ [0.04, 0.24] | 把"克制"理解成低对比，其实只是低彩度 |
| 3 | 圆角区间 | `--r-sm/md/lg/full` | 0–24px | 所有元素一个圆角，丢掉层级 |
| 4 | 边框 | `--line-*` `--border-w` | 0–2px，颜色 fg 4%–20% | 用浅灰边框代替"结构感" |
| 5 | 阴影 | `--shadow-*` | 无 / 单层 / 双层 / 硬偏移 | "几乎不用阴影"做成完全不用，浮层失去层叠 |
| 6 | 字重区间 | `--fw-*` | 300–800 | 把"克制"做成细字，可读性崩 |
| 7 | 动效强度 | `--dur-*` `--ease-*` | 80–400ms | "高级感"做成慢动画，实际是迟钝 |

---

## 每个维度的判据

### 1. 中性色温度

**问自己**：这个页面的灰，偏冷、偏暖、还是中性？

| 方向线索 | H | C |
|---|---|---|
| "工业""蓝图""仪表""瑞士""金属" | 240–260（蓝灰） | 0.002–0.006 |
| "纸张""印刷""温暖""手作" | 70–95（暖灰） | 0.002–0.008 |
| "医疗""洁净""纯净" | 180–200（青灰） | 0.001–0.004 |
| "严肃""法律""金融" | 250–270（蓝灰） | 0.003–0.008 |
| "复古""胶片" | 40–60（黄褐） | 0.006–0.012 |
| 无倾向 / 未提 | 85 | 0.002 |

**C 的护栏**：中性色的 C 一旦超过 0.012，就不再是"灰"而是"淡彩"，整页会显得脏。除非方向明确要"米色""奶油""沙色"。

**反例**：方向说"像瑞士铁路时刻表"，取了 `C = 0`。结果整页是纯灰，和任何默认 admin 模板无法区分——因为瑞士设计里那点冷蓝是它的签名。

### 2. 彩度上限

**问自己**：这页面上最鲜艳的东西有多鲜艳？出现了几次？

| 方向线索 | 主色 C | 强调色数量 |
|---|---|---|
| "克制""不抢戏""背景退后" | 0.06–0.10 | 1 处 |
| "专业""可信""企业" | 0.10–0.14 | 1–2 处 |
| "活力""年轻""消费" | 0.16–0.22 | 2–3 处 |
| "大胆""张扬""记忆点" | 0.20–0.28 | 3+ |
| 无倾向 | 0.10 | 1 处 |

**"低饱和"≠"低对比"**。把彩度做低的正确做法是收 C，不是把颜色调浅。浅色配浅底 = 对比度崩，和"克制"没关系。

**反例**：方向说"不要糖水感"，把主色从 `oklch(0.6 0.18 250)` 改成 `oklch(0.85 0.06 250)`。C 降了，L 也升了，结果按钮白得看不见。

### 3. 圆角区间

**问自己**：这个界面的"软硬"程度？四个角是直的、微圆、还是全圆？

| 方向线索 | sm / md / lg / full |
|---|---|
| "工业""图纸""锐利""硬边" | 0 / 0 / 0 / 999 |
| "克制""专业""瑞士" | 2 / 4 / 6 / 999 |
| "现代""产品""SaaS" | 6 / 10 / 16 / 999 |
| "友好""消费""轻松" | 8 / 12 / 20 / 999 |
| "玩具""儿童""趣味" | 12 / 20 / 28 / 999 |
| 无倾向 | 6 / 10 / 16 / 999 |

**必须四级不同**。`sm = md = lg` 等于放弃了层级——用户无法从形状判断"这是按钮还是卡片"。

**特例**：全 0 圆角的风格（粗野主义、图纸感）里，`--r-full` 仍然保留 999，用于头像、徽章、开关。除非方向明确说"连圆环都不要"。

### 4. 边框

**问自己**：结构靠什么建立——留白、边框、还是阴影？

| 方向线索 | 边框宽度 | 颜色 | 用在哪 |
|---|---|---|---|
| "图纸""表格""精确" | 1px | fg 8% | 所有容器 + 分隔 |
| "克制""极简" | 0–1px | fg 6% | 只在输入框与分隔线 |
| "厚重""海报""粗野" | 2px | fg 100% | 所有可交互元素 |
| "轻盈""漂浮" | 0 | — | 全靠阴影与间距 |
| 无倾向 | 1px | fg 8% | 分隔线 + 输入框 |

**边框不能同时承担"分隔"和"强调"**。同一页面上，分隔线浅、交互边框深，是两条不同的 token。

### 5. 阴影

**问自己**：这个界面的层叠感从哪来？

| 方向线索 | 策略 | 参数形态 |
|---|---|---|
| "平面""图纸""无阴影" | 无阴影，仅浮层一层 | `0 8px 24px -8px / .14`，只在弹层与下拉 |
| "克制""微妙" | 一层软阴影 | `0 1px 3px -1px / .10` |
| "材质""层叠""卡片" | 两级：贴地 + 抬升 | 见下方 |
| "海报""粗野""硬" | 硬偏移，无模糊 | `4px 4px 0 var(--fg)` |
| 无倾向 | 仅浮层一层 | 同第一行 |

**"几乎不用阴影"是最常被理解错的一维。** "不用"指的是不做装饰性投影；浮层（下拉、弹窗、toast）仍然需要阴影，否则用户看不出它浮在页面之上。这类阴影要写进合同，标注"仅用于浮层"。

两级阴影参考：

```css
/* 贴地：元素在页面上，微微离开 */
--shadow-1: 0 1px 2px -1px rgb(0 0 0 / .10), 0 2px 6px -2px rgb(0 0 0 / .08);
/* 抬升：元素脱离页面 */
--shadow-2: 0 4px 12px -4px rgb(0 0 0 / .12), 0 12px 32px -12px rgb(0 0 0 / .16);
/* 浮层：模态级别的分离 */
--shadow-3: 0 8px 24px -8px rgb(0 0 0 / .16), 0 24px 64px -24px rgb(0 0 0 / .22);
```

### 6. 字重区间

**问自己**：这个界面的"声音"多大？靠粗细还是靠字号建立层级？

| 方向线索 | body / strong / display |
|---|---|
| "克制""不用大字报""精密" | 400 / 500 / 600 |
| "专业""清晰" | 400 / 600 / 700 |
| "编辑感""杂志""有主张" | 400 / 600 / 700（但字号跨度大） |
| "大胆""海报""冲击" | 400 / 700 / 800 |
| "轻盈""优雅""高端" | 300 / 500 / 600 |
| 无倾向 | 400 / 600 / 700 |

**"不要大字报"的三种可能做法**（必须区分）：

1. 降字重（400/500/600）
2. 降字号跨度（48px → 32px）
3. 两个都降

**先问用户是哪个**，或者从上下文推断。多数时候真实诉求是 2——标题不需要那么大，而不是不需要那么粗。

**护栏**：body 不低于 300；同一字体在暗色下再降一档，所以浅色 body 最低取 400 才留得住降档空间。

### 7. 动效强度

**问自己**：交互反馈是"立刻"还是"有过程"？

| 方向线索 | 时长 | 缓动 | 位移 |
|---|---|---|---|
| "精密""工具""即时" | 80–140ms | `ease-out` | 无位移，仅颜色/透明度 |
| "克制""现代" | 120–200ms | `ease-out` | 0–4px |
| "流畅""产品" | 180–280ms | `cubic-bezier(.2,.7,.2,1)` | 4–8px |
| "有弹性""活泼" | 240–400ms | 弹簧 / `cubic-bezier(.34,1.56,.64,1)` | 8–16px |
| 无倾向 | 120–200ms | `ease-out` | 0–4px |

**"高级感"最常见的误解**：把动画做长做缓。实际上 400ms 以上在高频交互里会让人觉得"卡"，真正的质感来自**短而准**（120ms 内完成、缓动曲线干脆）。

## 完整示例

### 示例 A · 工业感 / 图纸感

> 用户原话："工业感、图纸感，像瑞士铁路时刻表那样克制。不要糖水渐变，不要大字报。"

| 维度 | 读到的 | 取值 | 依据 |
|---|---|---|---|
| 中性色温度 | 冷、几乎无彩 | `H 250, C 0.003` | "瑞士铁路时刻表" |
| 彩度上限 | 极克制，单点强调 | 主色 C ≤ 0.09 | "不要糖水渐变" |
| 圆角 | 接近直角 | `0 / 2 / 4 / 999` | "工业感"、"图纸感" |
| 边框 | 存在，细，承担结构 | `1px`，`fg 8%`，分隔线专用 | "图纸感" |
| 阴影 | 不做装饰投影，浮层例外 | 仅 `--shadow-3` | `null`（规则默认） |
| 字重 | 中等，靠字距与字号 | `400 / 500 / 600` | "不要大字报" |
| 动效 | 快、无回弹 | `100–140ms`，`ease-out` | `null`（规则默认） |

### 示例 B · 温暖 / 编辑感

> 用户原话："像一本装帧讲究的杂志。暖一点，但别做成咖啡馆那种。文字要有分量。"

| 维度 | 读到的 | 取值 | 依据 |
|---|---|---|---|
| 中性色温度 | 暖灰，纸张感 | `H 82, C 0.006` | "装帧讲究的杂志" |
| 彩度上限 | 中低，靠一处深色压场 | 主色 C ≤ 0.13 | "别做成咖啡馆那种"（避免高饱和暖色） |
| 圆角 | 极小，接近书页 | `0 / 2 / 3 / 999` | "装帧""杂志" |
| 边框 | 细线，横向为主 | `1px`，`fg 10%` | "杂志"的分隔线 |
| 阴影 | 不用 | 仅浮层 | `null` |
| 字重 | 正文有一定分量 | `400 / 600 / 700` | "文字要有分量" |
| 动效 | 短、无位移 | `120ms`，`ease-out` | `null` |

### 示例 C · 消费级 / 友好

> 用户原话："面向小学生的编程工具。要好玩，但别幼稚。家长也要看得懂。"

| 维度 | 读到的 | 取值 | 依据 |
|---|---|---|---|
| 中性色温度 | 中性偏暖 | `H 90, C 0.004` | 两个受众之间的折中 |
| 彩度上限 | 中高，多处使用但同一色相族 | 主色 C ≤ 0.18 | "好玩" |
| 圆角 | 明显圆润 | `10 / 16 / 24 / 999` | "好玩"但不"幼稚"→ 不是全圆 |
| 边框 | 无，靠阴影与间距 | 0，仅输入框 1px | "别幼稚"→ 不用卡通描边 |
| 阴影 | 一级软阴影 | `--shadow-1` | "好玩"提供轻量层叠 |
| 字重 | 中等，字号跨度大 | `400 / 600 / 700` | "家长也要看得懂"→ 不用细字 |
| 动效 | 有弹性但短 | `160–220ms`，`cubic-bezier(.34,1.56,.64,1)` | "好玩" |

## 反模式

| 反模式 | 表现 | 为什么错 |
|---|---|---|
| 只填一半 | 七个维度里四个写 `null` | 说明方向信息量不足，应该回 Phase 1 补问，不是硬凑默认 |
| 全填默认 | 七维全部等于"无倾向"那一行 | 等于没做转写，方向被丢掉了 |
| 依据造假 | `from` 里写一句用户没说过的"原话" | 日后审计时无法核对，比 `null` 更糟 |
| 维度串味 | 把"低彩度"做成"低对比"，把"少阴影"做成"零阴影" | 见上文各维度的"典型误判" |
| 一次定死 | 转写表确认后不再允许修改 | 用户在 Phase 3 看到合成页可能会改主意——允许回 P2.1 重转，只要重跑 G2 |

## 输出格式

写进 `decisions.json` 的 `translation` 段：

```json
"translation": {
  "neutralTemp": { "value": "H 250, C 0.003", "from": "像瑞士铁路时刻表" },
  "chromaCap":   { "value": 0.09,             "from": "不要糖水渐变" },
  "radius":      { "value": [0, 2, 4, 999],   "from": "工业感" },
  "border":      { "value": "1px / fg 8%",    "from": "图纸感" },
  "shadow":      { "value": "仅浮层",          "from": null },
  "weight":      { "value": [400, 500, 600],  "from": "不要大字报" },
  "motion":      { "value": "100-140ms ease-out", "from": null }
}
```

同时这张表要写进 `contract.md` 第 2 段，并成为回显给用户的表格。回显给用户时，表头与行名按 `phrasing.md` 换成白话（「七个方面 / 我从你的描述里读到的 / 取什么值 / 这条是从你哪句话推出来的」），`null` 说成「你没提过，我按常规默认取的」。

**`check-tokens.mjs` 会在 `translation` 为空时直接报错**，因为那意味着 G2 被跳过了。
