# 风格卡字段定义与写作规范

> 给维护者。执行时不需要读这一篇；写卡、改卡、加卡之前必须读。
> 风格卡是数据，不是散文（SKILL-DESIGN §2 D5）。散文无法驱动生成，也无法驱动校验。

---

## 1. 这个目录是什么

```
references/styles/
├── _schema.md          # 本文
├── style-index.json    # 唯一的计数来源：10 张卡 / 12 个变体
├── minimalism.md       # 逻辑卡，以下 10 张
├── bento.md
├── neumorphism.md
├── neo-brutalism.md
├── cyberpunk.md
├── dark-tech.md
├── pixel.md
├── material.md
├── gradient-aurora.md
├── glassmorphism.md    # 一张卡 → liquid / frosted / transparent 三个变体
└── custom.md           # "用户描述 → 风格卡"的转写方法，不是卡
```

**边界**：本目录只有描述。变体 CSS 在 `assets/studio/styles/`，夹具在 `assets/studio/fixture/`，两者由另一批产物负责。风格卡**不写选择器之外的内容**——不写文件路径、不写构建步骤、不写组件树。

**读数规则**：任何"有几张卡 / 几个变体"的判断都从 `style-index.json` 读，禁止手写、禁止从本目录的 `.md` 数量反推（`custom.md` 与 `_schema.md` 不是卡）。

## 2. 卡的八段结构

顺序不可变，标题文字不可变。缺段或改标题，视为坏卡。

| # | 段 | 作用 | 写作要求 | 常见错误 |
|---|---|---|---|---|
| 1 | 元信息 | 让人在 15 秒内决定要不要继续看 | 七行表格，逐项填空 | 一句话写成功能列表 |
| 2 | 签名特征 | 这个风格的**判别式** | 3–5 条，每条可证伪 | 写成形容词（"现代""简洁"） |
| 3 | Token 骨架 | 七维取值，落进语义 token | 只写差异项，值必须能用 | 发明新 token 名 |
| 4 | 典型配色 | 浅/深两套角色色 | 8 个角色一行不缺；标 ΔL 与对比度 | 只给主色，不给表面阶梯 |
| 5 | 标志性 CSS | 可复制的实现 | 4–8 段，只用 token | 出现裸色值、裸像素圆角 |
| 6 | 必须压制的东西 | 这个风格**不能容忍**什么 | 每条给机械原因 | 写"尽量少用"这种软话 |
| 7 | 验收 | 判断做对没有 | 可观测事实，可脚本可肉眼 | 写"整体感觉协调" |
| 8 | 反模式 | 最常见的做错方式 | 每条对应一个可指认的成品 | 与第 6 段重复 |

## 3. 字段定义

### 3.1 元信息

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | kebab-case | 必须等于文件名主干、等于 `style-index.json` 里 `cards[].id` |
| `变体` | 1 或 3 个 id | 除玻璃外，变体 id 与卡 id 相同；玻璃为 `glass-liquid` / `glass-frosted` / `glass-transparent` |
| `一句话` | ≤ 30 汉字 | 写**气质**与**手段**，不写用途。反例："适合后台管理系统" |
| `最适合` | 逗号分隔 3–4 项 | 写页面类型或内容形态，不写行业 |
| `不适合` | 逗号分隔 2–4 项 | 必须包含至少一个"能做但会付出代价"的场景 |
| `主要代价` | 一句 | 写这个风格**必然**要付的成本，不写"需要设计师"这种废话 |

`主要代价` 的判据：如果去掉它，卡还能成立，那它只是缺点不是代价。代价必须是风格定义的**反面**——粗野主义必然失去信息密度，玻璃必然赌性能与对比度，新拟态必然牺牲控件边界。

### 3.2 签名特征

**每条都必须能回答"如果去掉它，这还是这个风格吗？"** 答"是"的条目删掉。

写法：一条 = 一个可观测事实 + 一个量。

| 差 | 好 |
|---|---|
| 强调色很少 | 全站只有一个强调色，彩色面积占比 < 5% |
| 有硬阴影 | 所有浮起元素用 `4px 4px 0` 无模糊硬阴影，且零圆角 |
| 像素风 | 一切尺寸是 8 的倍数，1px 线只出现在 2px 硬描边里 |

数量 3–5。**5 是默认**；只有一条被另一条严格蕴含时才降到 4；降到 3 必须在卡里说明为什么不能拆分。

### 3.3 Token 骨架

七维固定顺序：中性色温度 → 彩度上限 → 圆角 → 边框 → 阴影 → 字重 → 动效。

**允许出现的 token 名（白名单）**：

```
--bg  --surface-1  --surface-2  --surface-3
--fg  --fg-muted  --accent  --line-1  --line-inset
--r-sm  --r-md  --r-lg  --r-full
--shadow-1  --shadow-2  --shadow-3
--fw-body  --fw-strong  --fw-display
--dur-fast  --dur-base  --dur-slow  --ease-out  --ease-inout
```

规则：

1. **卡里不许发明新 token**。如果某个风格真的需要 `--glow-color`，那是 `base.css` 或变体 CSS 的局部变量，不进卡、不进合同。
2. **只写差异项**。`--s-*` / `--fs-*` / `--lh-*` 全风格共用基线，卡里不重复。
3. 每个值都要能直接写进 CSS。写"中等圆角"是无效值；写 `--r-sm 6 / --r-md 10 / --r-lg 16` 才是。
4. 阴影写全 `--shadow-1` / `--shadow-2` / `--shadow-3` 三档语义：贴地 / 抬升 / 浮层。不用阴影的风格把前两档写 `none`，第三档必须保留——**浮层没有阴影用户就看不出它浮在页面上**（translation.md 第 5 维）。
5. 字重必须给浅色与暗色两套，暗色降一档（R5）；同时声明该卡的字重阶梯，方便 `weightLadder.available` 做映射。

### 3.4 典型配色

固定 8 行，顺序：`--bg`、`--surface-1`、`--surface-2`、`--surface-3`、`--fg`、`--fg-muted`、`--accent`、`--line-1`。

每格写 `#HEX · oklch(L C H)`。表下必须补三行事实：

- 表面 ΔL 三档（必须是 0.010–0.030 的绝对值，不是"1%"）
- 正文 / 次要 / 强调 对 bg 的对比度
- 暗色对应值是否重新映射（不允许只是反转）

**着色规则**：同一卡内四个表面共享 H 与 C，只动 L（SKILL-DESIGN §4.6）。色相漂移 > 2° 会让阶梯显脏。

### 3.5 标志性 CSS

- **4–8 段**，每段一个小标题 + 一个代码块。
- 第一段固定是完整 token 覆盖（`:root[data-style="<variant>"]` + 暗色块），后面是 3–7 条签名规则。
- 只用白名单 token；确实需要局部变量时，变量名必须带风格前缀（`--brut-offset`），且在同一代码块里定义。
- **每段代码块最后一行注释写"要验证什么"**，例如 `/* 验收：此处 computed border-radius 必须是 0 */`。
- 不写 `@import`、不写选择器以外的东西。

### 3.6 必须压制的东西

表格两列：`不要出现` / `原因`。原因必须是**机械的**，不能是审美判断。

| 差 | 好 |
|---|---|
| 不要用渐变 | 渐变会与硬阴影争夺焦点，且让 2px 描边的边缘看起来发虚 |
| 不要用太多颜色 | 超过 2 个高饱和色后，撞色的"记忆点"变成噪点，且无法通过 3:1 非文本对比 |

至少 4 行。这里的每一条都应该能被 reviewer 在截图里指出来。

### 3.7 验收

- 每行一个 `- [ ]`，只写**可观测事实**：computed 值、存在/不存在、数量上限、对比度数字。
- 至少 6 条，其中至少 3 条能被 `audit.mjs` / `check-tokens.mjs` 自动判。
- 不写"整体协调""有呼吸感"。

### 3.8 反模式

表格两列：`常见做错` / `为什么错`。与第 6 段的区别：第 6 段是**元素级禁令**，这里是**组合级误用**（"把两个风格拼在一起""只抄了配色没抄结构"）。

至少 4 行。

## 5. 加卡与改卡

### 5.1 先判断：是不是新卡

按 `custom.md` 的判据走。**默认答案是"不是"**：绝大多数"新风格"是已有卡 + 配色覆盖。真正的新卡必须满足至少两条：

1. 七维里有 ≥ 3 维落在所有现有卡区间之外；
2. 有一个现有卡无法容纳的签名特征（结构级，不是配色级）；
3. 它的 anti 列表与所有现有卡不冲突——如果有冲突，说明它是某张卡的变体，不是新卡。

### 5.2 新卡的代价

加一张卡会打破"10 卡 / 12 变体"的口径，而这句口径写在 SKILL.md、SKILL-DESIGN.md 与 Studio 里。因此：

- 加卡必须同时改 `style-index.json`、SKILL.md §3、SKILL-DESIGN.md §1.2/§5.2，三处口径一致；
- 必须同步新增一个 CSS 变体文件，否则 index 与磁盘不一致，批次 6 验收直接失败；
- 玻璃那种"一卡多变体"的拆法必须单独说明，并写清判定法（遮住背景看是变形、糊了、还是只染色）。

没有走完这三步的"新卡"只能作为 `custom.md` 的一次性转写，不进 index。

### 5.3 改卡的约束

| 改动 | 必须同步 |
|---|---|
| 改 `id` | 文件名、index 的 cards 与 variants、卡片内所有提及 |
| 改配色 | 表下 ΔL 与对比度三行、CSS 第一段的 token 值 |
| 改签名特征 | 对应 CSS 段、验收清单 |
| 改 anti | `必须压制的东西` 表、以及所有引用这张卡的其他卡（例如粗野主义的 anti 会影响 material 的"不要照抄"段落） |

## 6. 与其他文件的关系

| 文件 | 关系 |
|---|---|
| `SKILL.md` §2 Phase 1 | 候选推荐只读卡 id 与"最适合/不适合"，不读正文。正文只在选中后加载 |
| `references/translation.md` | 卡是**别人写好的转写表**。卡里的七维值就是 Phase 2 的输入，用户改哪一维，就只覆盖那一维 |
| `references/rules/*` | 规则优先于风格。风格卡可以声明 R3/R4 的**例外方案**，但必须写清等价物与登记方式 |
| `SKILL-DESIGN.md` §5.3 | 玻璃卡的技术事实必须与之一致；**不许新增未经核对的技术断言** |
| `assets/studio/styles/style-index.json` | 计数镜像。两处不一致时以 `assets/studio/styles/` 为准（它是渲染时真正读的那份），并在同一提交里修正本目录这份 |
